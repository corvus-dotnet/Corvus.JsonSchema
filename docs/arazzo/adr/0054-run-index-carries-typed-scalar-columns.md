# ADR 0054. The run index carries typed scalar columns, not bytes-native values

Date: 2026-07-26. Status: **Accepted**. Scope: how `WorkflowRunIndexEntry` represents the fields a store indexes alongside the opaque checkpoint.
This records why the run index holds its scalar fields (the workflow id, environment, error type, the awaiting channel and correlation ids, and the run correlation id) as managed strings, while the checkpoint payload and the tag sets stay bytes-native. It is a corollary of [ADR 0037](0037-bytes-native-seams.md), settled here so the recurring "why realise a string only to re-encode it" question is not relitigated.

## Context

A checkpoint save carries two things to a store. The opaque checkpoint bytes, which the backend persists by id and never parses, and a `WorkflowRunIndexEntry`, the handful of projected fields the backend indexes so it can answer the Tier-2 wait queries (runs that are due, or awaiting a correlation) and the control-plane visibility queries (runs by status, workflow, error, or environment). `WorkflowRunIndexEntry` holds `Tags` and `SecurityTags` as bytes-native deferred holders, but its six scalar fields as managed `string`. ADR 0037 makes bytes-native the default for a value moving through the persistence layer, so a reasonable challenge is whether these strings are the record-to-document round-trip the discipline forbids, with bytes in, a string realised, and the string re-encoded out.

The answer is that a queried scalar's genuine leaf already is a typed column, so the string is the leaf form rather than a round-trip. The reconnaissance below establishes it across every backend.

### Grounded architectural facts

- **The index is a queried projection, not a shuttled payload.** Its fields back real predicates. The SQL backends filter `WHERE workflow_id IN (...)`, `environment = @e`, and `awaiting_channel = @c` over dedicated `TEXT` columns and indexes; Mongo builds `b.Eq("awaitingChannel", ...)`; Cosmos runs `c.environment = @e`; Azure Table filters on OData string equality. The dispatch and wait interfaces (`IWorkflowDispatchIndex`, `IWorkflowWaitIndex`) pass and return managed strings, taking `IReadOnlyCollection<string>` hosted ids and `string? runnerEnvironment` and yielding `WorkflowRunId`.
- **Every backend consumes the scalars as a managed string.** Postgres and SqlServer bind them as `Text` parameters; Azure Storage sets them as `TableEntity` string properties; Redis writes them as hash field values (a `RedisValue` from a `string`); the JSON-native stores (Cosmos, Mongo, NATS) emit them with `writer.WriteString(nameUtf8, value)`, where only the property name is UTF-8 and the value is the managed string. No backend keeps a scalar bytes-native, because the driver and serializer sinks each require a managed string.
- **The tag sets are bytes-native for a reason the scalars do not share.** `Tags` and `SecurityTags` stay bytes because they are matched by native container operators that never materialise the stored row. `ARRAY_CONTAINS(c.tags, @tag)` in Cosmos, `b.All("tags", ...)` in Mongo, and `tags LIKE @tag` in Postgres realise only the query needle. A scalar has no such operator. It is equality-matched or bound as a single value, so its leaf is a typed column.
- **The primary producer already holds live strings.** `WorkflowRun` carries `WorkflowId`, `CorrelationId`, and `Environment` as managed string fields, because the run itself uses them for dispatch, telemetry, and logging. `WorkflowRunIndexEntry.Project` on every in-process checkpoint copies those references, so the primary path allocates no string per index field. A bytes-native field would add an encode here, and then a decode at every backend.
- **One path realises the scalars from bytes.** The serverless runner ([ADR 0028](0028-pluggable-execution-backends.md)) receives only the function's checkpoint bytes over its checkpoint surface, so `WorkflowCheckpointSerializer.ProjectIndex` re-projects the index from those bytes and does realise the scalars with `GetString`. That is the deliberate consequence of keeping the checkpoint POST minimal, carrying the bytes and a write-sequence rather than the index, which avoids serialising the tag payload onto the wire a second time when it is already inside the checkpoint bytes. `ProjectIndex` is the lean form. It reads the scalars, copies the tags as bytes, and skips the pooled maps and collections a full deserialize would build.

## Decision

`WorkflowRunIndexEntry` carries its scalar fields as managed strings and its tag sets as bytes-native deferred holders, and the checkpoint stays opaque bytes. This is consistent with ADR 0037, not an exception to it. The "realise at leaf" rule already names a searchable indexed column as a genuine leaf, and for a queried scalar the leaf is exactly a typed column or parameter, so a string is the leaf form rather than a round-trip. Bytes-native stays reserved for what benefits from it, which is the opaque checkpoint the store never parses and the collection tags matched by container operators that never materialise the stored row.

The serverless runner's re-projection is accepted as the cost of the bytes-only checkpoint wire. If serverless per-step checkpoint throughput ever becomes the bottleneck, the lever is the wire, not the index representation. Carry the projected index alongside the bytes, trading a larger POST body and a redundant tag serialisation for skipping the re-projection.

## Consequences

- The in-process checkpoint path, which runs for every step of every run, allocates no string per index field. It copies references from already-realised run state.
- A bytes-native index would not remove the realisation. It would relocate it to each of the twelve backend leaves, which all require a managed string, and add an encode on the primary path. That is a net loss, so it is not adopted.
- The rule to remember is a category test. An opaque payload the store never inspects, or a collection matched by a native container operator, is bytes-native. A scalar that is equality-matched or bound as a single value has a typed column for a leaf, so it is a string. Applying bytes-native to a queried scalar is a category error, not a discipline win.
- The serverless runner pays one lean re-projection per checkpoint, isolated to that backend. If it ever dominates, revisit the wire shape under ADR 0028, not this decision.
