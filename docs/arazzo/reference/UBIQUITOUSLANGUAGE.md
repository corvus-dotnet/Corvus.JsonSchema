# Ubiquitous language

A living glossary of the terms this project uses, in the Domain-Driven Design sense: one name per
concept, used consistently in code, documents, APIs, UI copy, and conversation. **Maintained at the
root of the Arazzo design-docs folder; update it in the same change that introduces or refines a
term.** If a term here conflicts with usage elsewhere, this document wins and the other usage should
be fixed. Known conflicts and their resolutions are recorded in
[Normalization decisions](#normalization-decisions) at the end.

Sections, and the entries within each section, are ordered alphabetically. Where a definition uses
another entry's term (in exact or inflected form), its first use links to that entry.

Terms marked **(proposed)** are being introduced by in-flight design work and settle when that
design lands.

## API mechanics

| Term | Definition |
|------|------------|
| <a id="keyset-pagination"></a>**Keyset pagination** | The project-wide list idiom: `limit` + opaque `pageToken` in, `nextPageToken` out, ordered by a stable per-store key. Every list endpoint *and its store* is paged from the start. |
| <a id="problem-details"></a>**Problem details** | Errors are RFC 9457 `application/problem+json` (`type`, `title`, `status`, `detail`, `instance`); clients branch on status, never parse strings. |

## Arazzo document model

| Term | Definition |
|------|------------|
| <a id="action"></a>**Action** | A success action (`end`, `goto`) or failure action (`end`, `goto`, `retry` with `retryAfter`/`retryLimit`), attached to a [step](#step) or inherited from the [workflow](#workflow) level. |
| <a id="arazzo-document"></a>**Arazzo document** | A document conforming to the Arazzo specification (1.0/1.1): `info`, `sourceDescriptions`, one or more `workflows`, optional `components`. The unit the [workflow designer](#workflow-designer) edits and the [catalog](#catalog) stores. |
| <a id="components"></a>**Components** | The [Arazzo document](#arazzo-document)'s reusable library (`inputs`, `parameters`, `successActions`, `failureActions`) referenced via reusable objects. |
| <a id="criterion"></a>**Criterion** | A success/assertion condition (`simple`, `regex`, `jsonpath`, `xpath`) with optional `context` [runtime expression](#runtime-expression). Used in [step](#step) `successCriteria`, in [action](#action) `criteria`, and in [scenario](#scenario) `$outputs` expectations (judged by the same compiler). |
| <a id="implicit-dependency"></a>**Implicit dependency** (step) | An ordering edge a [step](#step) imposes not by declaring `dependsOn` but by reading another same-[workflow](#workflow) step's data through a `$steps.<id>.*` [runtime expression](#runtime-expression) (Arazzo 1.1 §5.8.5.2.4): the referenced step MUST complete first. The generator folds implicit dependencies into the same topological order as explicit `dependsOn` (`WorkflowExecutorEmitter.TopologicallyOrder`); a cycle in the combined graph is an error. Contrast **explicit dependency** (a `dependsOn` entry). |
| <a id="operation-surface"></a>**Operation surface** | The set of operations (OpenAPI) or channel operations (AsyncAPI) a [source document](#source-document) exposes; what a user browses to create [steps](#step). Described by `OperationDescriptor` / `AsyncApiChannelDescriptor`. |
| <a id="runtime-expression"></a>**Runtime expression** | An Arazzo `$…` expression (`$inputs`, `$steps`, `$outputs`, `$response`, `$statusCode`, …) evaluated during execution; parsed by `ArazzoExpression`. |
| <a id="source-description"></a>**Source description** | An entry in the [Arazzo document](#arazzo-document)'s `sourceDescriptions`: a named reference (`name`, `url`, `type` = `openapi` \| `asyncapi` \| `arazzo`) to a [source document](#source-document). In-document; distinct from a *source document* (the file itself) and a *[registered source](#registered-source)* (a `/sources` registry entry). |
| <a id="source-document"></a>**Source document** | The actual OpenAPI/AsyncAPI/Arazzo file a [workflow](#workflow)'s [steps](#step) bind against; stored inside the [package](#package) as `sources/<name>.json`. |
| <a id="step"></a>**Step** | One unit of work in a [workflow](#workflow). Binds to exactly one of: an OpenAPI operation (`operationId` or `operationPath`), another workflow (`workflowId`), or an AsyncAPI channel (`channelPath`, 1.1). Carries `parameters`, `requestBody`, `successCriteria`, `onSuccess`/`onFailure` [actions](#action), and `outputs`. |
| <a id="workflow"></a>**Workflow** | A named sequence of [steps](#step) within an [Arazzo document](#arazzo-document) (`workflowId`, `inputs` schema, `steps`, workflow-level `successActions`/`failureActions`, `outputs`, `parameters`, `dependsOn`). |

## Catalog and lifecycle

| Term | Definition |
|------|------------|
| <a id="baked-schemas"></a>**Baked schemas** | The precomputed `metadata/schemas.json` [package](#package) entry: per-[step](#step) schema metadata (typed inputs, resolved output types) that drives `/validate` and the UI's typed forms without re-parsing [source documents](#source-document). |
| <a id="base-workflow-id"></a>**Base workflow id** | The unversioned [workflow](#workflow) identity (`nightly-reconcile`) under which [versions](#version) group. |
| <a id="catalog"></a>**Catalog** | The control plane's immutable, [content-hashed](#content-hash), versioned store of [workflow](#workflow) [packages](#package), with governance metadata and search. |
| <a id="content-hash"></a>**Content hash** | SHA-256 over the RFC 8785 canonical form of the logical `{workflow, sources}` content — framing-independent, stable across repacks. The [version](#version)'s identity and the [executor](#executor)'s integrity binding. |
| <a id="draft"></a>**Draft** | **A [version](#version) not yet made [available](#availability) in any [environment](#environment).** A derived state (its availability set is empty), not a stored flag. A draft is exercised by [scenarios](#scenario) in the [workflow designer](#workflow-designer), then [promoted](#promotion) through environments. Once available anywhere it is no longer a draft. |
| <a id="executor-manifest"></a>**Executor manifest** | The `metadata/executor-manifest.json` [package](#package) entry: target framework, assembly digest, package-hash binding, entry type. Verified before an [executor](#executor) loads. |
| <a id="obsolete"></a>**Obsolete** | The retired governance status of a [version](#version) (`Active` → `Obsolete`); still addressable until [purged](#purge), never deletable while [runs](#run) reference it. |
| <a id="package"></a>**Package** (`.awp`) | The self-contained, deterministic, [content-hashed](#content-hash) container for a [version](#version): the [Arazzo document](#arazzo-document), every referenced [source document](#source-document), and named metadata entries. A complete input to code generation. |
| <a id="publish"></a>**Publish** | The act of minting a catalog [version](#version) from a [working copy](#working-copy), together with its [scenarios](#scenario) and the [evidence](#evidence) of their successful execution. A published-but-unpromoted version is a [draft](#draft). (Serving a version at an endpoint is *hosting*, not publishing — see normalization E.) |
| <a id="purge"></a>**Purge** | The destructive bulk-reap of [obsolete](#obsolete) [versions](#version), or of old completed/cancelled [runs](#run), that nothing references. Gated by a `:purge` [capability scope](#capability-scope) and bounded by purge [reach](#reach). |
| <a id="runnable"></a>**Runnable** | A [version](#version) that carries a compiled [executor](#executor) (code generation and compile succeeded at add). Only runnable versions can be [triggered](#trigger). |
| <a id="version"></a>**Version** (catalog version) | One immutable release of a [base workflow](#base-workflow-id): the [package](#package) plus governance metadata. The store assigns `versionNumber` and rewrites the workflow id to `{base}-v{n}` (the **workflow-id rewrite**). Content never changes after add; only governance metadata is mutable. |
| <a id="working-copy"></a>**Working copy** | The mutable [Arazzo document](#arazzo-document) under edit in the [workflow designer](#workflow-designer), with its [scenarios](#scenario). Durably saveable on its own, as many times as needed, without ever minting a catalog [version](#version) — so development iteration does not pollute the [catalog](#catalog). Persisted in the designer workspace (and optionally a Git branch); *[publish](#publish)* mints a catalog version from it. Prefer this term over "draft save": **[draft](#draft)** is reserved for an unpromoted catalog version. |

## Design, test, and validation

| Term | Definition |
|------|------------|
| <a id="advanced-node"></a>**Advanced node** | A schema construct the [schema editor](#schema-editor)'s visual tier summarises rather than fully forms — a keyword it does not render, `not`, `patternProperties`, a `$ref` carrying siblings, and the like. Shown as a labelled row that preserves the raw subschema and stays JSON-editable, so a round-trip never destroys or reorders it. |
| <a id="busy-action"></a>**Busy action** | A user-triggered service call wrapped by `runAction(trigger, work)` on `ArazzoElement`: the trigger is blocked from re-firing the instant it is activated (so a double-click issues the operation once), and if the work outlives about 150ms the trigger shows a spinner in place of its label. It leaves `disabled` to validation, spins only the network portion of a confirm-gated action, and is a courtesy against a double submission, never a substitute for server-side idempotency ([ADR 0053](../adr/0053-triggered-actions-guard-and-show-delayed-busy.md)). |
| <a id="change-classification"></a>**Change classification** | The label a [comparison](#comparison) assigns each element: *added* (present only on the right), *removed* (present only on the left), *changed* (present on both, content differs), *renamed* (a [step](#step) matched by binding under a new id — see [rename](#rename-step)), *moved* (a step reordered, content identical — never *changed*). |
| <a id="comparison"></a>**Comparison** (workflow) | A structured diff of two [workflow](#workflow) [versions](#version) (`diffWorkflowPair`): [steps](#step), flow edges, and workflow-level surfaces classified as added / removed / changed / renamed / moved (the [change classification](#change-classification)) on top of the graph projection and the document model's identity-aware structural diff. Rendered by `<arazzo-workflow-compare>` as side-by-side, overlay, or text (the [comparison modes](#comparison-mode)). |
| <a id="comparison-mode"></a>**Comparison mode** | The [comparison](#comparison)'s presentation, per dialog instance: **Side by side** (two surfaces), **Overlay** (one union canvas, the base [version](#version) solid and the other side's exclusives translucent as *ghosts*), or **Text** (a CodeMirror MergeView over the two serialized documents). |
| <a id="debug-run"></a>**Debug run** | The durable, forward-only server-side entity a [debug session](#debug-session) drives (REST `debugRuns` tag, §18): started from a [working copy](#working-copy), run/paused/stepped, resumable, and cancellable/deletable. Backed by a real [executor](#executor) whose transport is either a [scenario](#scenario)'s [mock transport](#mock-transport) or a live transport in a development-class [environment](#environment); forward-only means time-travel is a replay over the recorded [trace](#trace), not a rewind of the run. |
| <a id="debug-session"></a>**Debug session** | An interactive [simulation](#simulation) in the [workflow designer](#workflow-designer): run/pause/step a [workflow](#workflow) on the design surface against a [scenario](#scenario)'s [mock transport](#mock-transport) and [virtual clock](#virtual-clock), with breakpoints on [steps](#step), live state inspection, expression evaluation against the paused context, [trigger injection](#trigger-injection), and time-travel over the recorded [trace](#trace). |
| <a id="edge-corridor"></a>**Edge corridor** | The vertical gap — between adjacent nodes of a rank band, or just outside the row — that a band-skipping edge routes through on the [workflow designer](#workflow-designer)'s design surface, one waypoint per crossed band, so it runs beside the [steps](#step) and chain edges it would otherwise cut through. Straight wins: an edge keeps its own straight line where it already clears the band; only a line that would pierce a node snaps to the nearest corridor (`routeEdges`, design §6.3). |
| <a id="edge-lane"></a>**Edge lane** | An edge's slot within a shared [edge corridor](#edge-corridor) — or, for an upward retry/goto loop, its right-side vertical track: deterministic offsets a fixed pitch apart, ghosts sorted after solid edges, so no two edges draw the same line. The [comparison](#comparison) overlay relies on this to keep a ghost edge visible beside the chain it bridges. |
| <a id="evidence"></a>**Evidence** | The durable record that a [version](#version)'s [scenarios](#scenario) executed successfully: the scenario set (by [content hash](#content-hash)), per-scenario outcomes, and the engine/version identity, attached at [publish](#publish) and surfaced by the [catalog](#catalog). |
| <a id="guarded-json-editor"></a>**Guarded JSON editor** | A parse-gated raw-JSON textarea whose edits apply only when the buffer parses, holding the last valid value otherwise (`wireGuardedJson`). Per host, a blank buffer either deletes the value or holds the last valid one. The single shared idiom behind the [schema editor](#schema-editor)'s JSON tier, the payload editor, and the document inspector. |
| <a id="merge-target"></a>**Merge target** | The side of a [comparison](#comparison), opened with `mergeTarget: true`, whose document the host is editing (the [working copy](#working-copy)). It turns the comparison into an interactive merge and sources its document from the live model, never a snapshot. |
| <a id="mock-transport"></a>**Mock transport** | The simulated transport (`MockApiTransport`) that answers the operations a [workflow](#workflow)'s [source documents](#source-document) expose during a [simulation](#simulation), with scripted responses instead of real endpoints. (Not a *[runner](#runner)* — the [executor](#executor) is real; its transport and clock are simulated.) |
| <a id="rename-step"></a>**Rename** (step) | A [step](#step) matched across [versions](#version) by binding equality (same `operationId` / `operationPath` / `channelPath`+action / `workflowId`) under a different `stepId`. Presented as one changed step with a rename note, never a remove plus an add. |
| <a id="scenario"></a>**Scenario** | A named, declarative test for a [workflow](#workflow): inputs, scripted [mock-transport](#mock-transport) behaviour, triggers, [virtual-clock](#virtual-clock) advances, and expected outcomes/paths/outputs. Associated with the [version](#version) under design; carried forward when a new version of a published workflow is edited. |
| <a id="scenario-runner"></a>**Scenario runner** | The CLI (`scenarios run`) that executes a globbable set of [scenarios](#scenario) against a [workflow](#workflow) — in-process via the [simulator](#simulation) (standalone, no control plane) or against a control plane — with CI-grade reports and exit codes; wrappable as a GitHub Action. |
| <a id="schema-editor"></a>**Schema editor** | The typed JSON-Schema authoring form (`<arazzo-schema-editor>`) for a [workflow](#workflow)'s `inputs` and the [components](#components) library's input schemas, in place of a raw textarea. Edits a *subset* of JSON Schema as typed property rows and first-class `oneOf`/`anyOf`/`allOf` combiner nodes, stays lossless over the rest via **[advanced nodes](#advanced-node)**, offers a Form \| JSON toggle over the **[guarded JSON editor](#guarded-json-editor)**, a live typed preview, and a shared-type reference picker. |
| <a id="simulation"></a>**Simulation** | Executing a [workflow](#workflow)'s compiled [executor](#executor) against the [mock transport](#mock-transport) and [virtual clock](#virtual-clock), producing a [trace](#trace). Deterministic and replayable. |
| <a id="take-keep"></a>**Take / Keep** | The interactive-merge verbs on a change-list entry when there is a [merge target](#merge-target). *Take* adopts the other side's state for that one entry (the component emits `change-accepted`/`merge-text-applied`; the host applies it to its model, undoably). *Keep* marks the entry reviewed for the session — the [working copy](#working-copy) IS the merge state, so a change not taken is kept by definition; nothing is persisted. |
| <a id="trace"></a>**Trace** | The structured record of one [simulation](#simulation): the path taken, per-[step](#step) requests/responses, [criterion](#criterion) results, retries, [waits](#wait), outputs, and final outcome. |
| <a id="trigger-injection"></a>**Trigger injection** | Delivering a message trigger into a [debug run](#debug-run) that is `Suspended` on a message [wait](#wait) (REST `injectDebugRunMessage`): the payload is handed straight to the suspended run's correlated wait to [resume](#resume) it — nothing is published to a broker — so a message-driven [workflow](#workflow) can be driven interactively without an out-of-band producer. |
| <a id="virtual-clock"></a>**Virtual clock** | The simulated `TimeProvider` a [simulation](#simulation) runs against, so timer [waits](#wait) and retries elapse deterministically without real time passing. |
| <a id="workflow-designer"></a>**Workflow designer** | The UI for authoring an [Arazzo document](#arazzo-document): a visual design surface (diagram area + context inspector) and a text editor over the same [working copy](#working-copy). The design surface doubles as the interactive debugger for [simulations](#simulation) (the [debug session](#debug-session)) — it is an instrument, not an illustration. |

## Environments and promotion

| Term | Definition |
|------|------------|
| <a id="availability"></a>**Availability** | The many-to-many relation "[version](#version) V is available in [environment](#environment) E". Additive; governed by the target environment's [administrators](#environment-administrator). |
| <a id="availability-matrix"></a>**Availability matrix** | The [version](#version) × [environment](#environment) grid showing each pair as [available](#availability), promotable, or not [ready](#readiness), with direct make/withdraw or request-[promotion](#promotion) actions. |
| <a id="availability-request"></a>**Availability request** | A request that a [version](#version) be made [available](#availability) in an [environment](#environment), routed to that environment's [administrators](#environment-administrator)' [approver inbox](#approver-inbox) (approve/deny/withdraw). The environment-scoped sibling of an [access request](#access-request), decided under the same [independent-decision](#independent-decision) rule. |
| <a id="environment"></a>**Environment** | A first-class governed deployment target ([administrator](#environment-administrator) set, audit) that [versions](#version) are made [available](#availability) in and [credentials](#credential) are bound per. |
| <a id="environment-administrator"></a>**Environment administrator** | A member of an [environment](#environment)'s governing set; approves [availability](#availability-request) and [runner-authorization](#runner-environment-binding) requests for that environment. The environment-scoped counterpart of a workflow [administrator](#administrator). |
| <a id="environment-checkpoint-key"></a>**Environment checkpoint key** | A sealed [environment](#environment)'s key registration (ADR 0065). Each generation names the payload-key id its [checkpoint payloads](#checkpoint-payload) carry (the [payload key](#payload-key) itself stays in the tenant's custody, runner-side), plus the public **seal key** the control plane wraps run-start inputs to. Registering a new generation is a rotation, and the registrant signs a framed tuple naming the environment, key id, key, and signing instant with the private seal half, so a registration proves possession rather than being a string anyone can write. The proof is bounded: it establishes control of the seal pair, and cannot establish that the symmetric [payload key](#payload-key) exists, since that key must never reach the control plane. Replaying a registration re-registers the identical generation and changes nothing, which is what removes the need for a server-issued challenge. Managed through `/environments/{name}/keys`, under the environment's administrators. Retiring the last active generation is refused while more than one [owner group](#owner-group) exists. The control plane never holds a key that opens tenant data. |
| <a id="promotion"></a>**Promotion** | Making a [version](#version) [available](#availability) in an [environment](#environment), either directly ([environment administrator](#environment-administrator)) or via an [availability request](#availability-request) through the [approver inbox](#approver-inbox). [Readiness](#readiness)-gated. |
| <a id="readiness"></a>**Readiness** | The gate on [promotion](#promotion): every [registered source](#registered-source) the [version](#version) references must have a [usable](#usability) [credential](#credential) in the target [environment](#environment), and — where the environment sets `requireEvidence` — the version's [publish](#publish) [evidence](#evidence) must attest a **green suite** (at least one [scenario](#scenario) ran, none failed). Absent evidence, or an empty suite, counts as unevidenced and is refused there. Per-environment and default-off, so environments that never opt in keep the credential-only gate. |

## Execution

| Term | Definition |
|------|------------|
| <a id="aot-builder"></a>**AOT builder** (workflow AOT builder) | The control-plane build tooling that Native-AOT compiles a [version](#version)'s [native binary](#native-binary) from its already-signed [executor](#executor) IL (ADR 0055). It verifies the [executor manifest](#executor-manifest) signature before it compiles, so the native binary is provably derived from the signed IL, and builds one binary per runtime target. |
| <a id="checkpoint"></a>**Checkpoint** | The single small JSON document per [run](#run) that *is* the entire resumable state: [cursor](#cursor), [step](#step) outputs, retry counters, correlation tokens, inputs, [wait](#wait), [fault](#fault), history, etag. |
| <a id="checkpoint-digest"></a>**Checkpoint digest** *(proposed)* | The SHA-256 over a [checkpoint](#checkpoint)'s pinned submitted bytes (header, runner region, salt, nonce, tag, ciphertext, MAC), which is that checkpoint's *identity* in the [tenant anchor](#tenant-anchor) (ADR 0065). Never the server-owned control-plane region, which is joined at read time and is not the [runner](#runner)'s to commit to. Always qualified. Bare "digest" means the [identity digest](#digest). |
| <a id="checkpoint-envelope"></a>**Checkpoint envelope** | The control-plane-readable half of a [checkpoint](#checkpoint) (ADR 0065): the run-management structure — [cursor](#cursor), status, [wait](#wait), [fault](#fault) classification, retry counters, sequencing, timing — every governance verb acts on. Clear by design so the control plane governs every [run](#run); contains no tenant data. |
| <a id="checkpoint-payload"></a>**Checkpoint payload** | The tenant-data half of a [checkpoint](#checkpoint) (ADR 0065): run inputs, [step](#step) outputs, extracted values. In a sealed [environment](#environment) the [runner](#runner) encrypts it (AES-GCM under the environment's payload key, AAD-bound to run + sequence + [cursor](#cursor)) before it leaves the runner's boundary — opaque to the control plane and to every other tenant. |
| <a id="claim"></a>**Claim** | Taking a claimable [run](#run) and its [lease](#lease) in one operation, the only way a [runner](#runner) is given work (ADR 0065). Claimable means a `Pending` run, a `Running` one whose lease has lapsed (an orphan a crashed runner left, which must be reclaimable or an interrupted run would never [resume](#resume)), or one the control plane marked resume-claimable. The candidate set is intersected server-side with the [environments](#environment) the runner's machine principal is bound to, which is why the environment is never a request parameter: a runner asking for one would be asking to claim another tenant's work. |
| <a id="correlation-id"></a>**Correlation id** | The key a message [wait](#wait) matches on, so an inbound message [resumes](#resume) exactly the [run](#run) that awaits it. Absence on either side widens the match rather than narrowing it; see [correlation match](#correlation-match). |
| <a id="cursor"></a>**Cursor** | The scalar state-machine position in a [run](#run)'s [checkpoint](#checkpoint) identifying which [step](#step) runs next; the core of [resume](#resume). |
| <a id="correlation-match"></a>**Correlation match** | The rule deciding whether a delivered message resumes a [run](#run) awaiting one. Absence is a wildcard on either side: a message carrying no [correlation id](#correlation-id) reaches every run awaiting the channel, and a run awaiting no particular correlation is reached by any message on it. Only two correlations that are both present and different fail to match. Pinned by the conformance suite across every backend, so it is the rule everywhere rather than one store's behaviour. |
| <a id="dispatch-pass"></a>**Dispatch pass** | One sweep of a [runner](#runner)'s dispatch loop: [claim](#claim) a [run](#run), [resume](#resume) it, release it, repeat until nothing is claimable or the pass hits its bound. The bound is what stops a backlog monopolising the runner, so a pass ending with work still queued is the design rather than a shortfall; the next pass takes the rest. Release happens on every exit path including cancellation, because cancellation is how a runner shuts down and a lease not given back strands its run until the TTL lapses. |
| <a id="enrolment-token"></a>**Enrolment token** | A short-lived, [environment](#environment)-scoped bearer token that admits a [runner](#runner) no [administrator](#environment-administrator) has named in advance (ADR 0065 decision 2). An administrator mints one and the deployment delivers it to the runners it starts there; a runner holds a token rather than the secret that mints them, because the secret would let it enrol any id for as long as it held it. Presenting one binds the authorization to the presenting [machine principal](#machine-principal) and enters `Pending`, so it buys a place in the approval queue rather than the right to execute. It is the alternative to [pre-authorization](#runner-pre-authorization), and the one that lets an environment scale its runners: pre-authorizing per instance otherwise requires something holding the standing power to pre-authorize any id, which is the blanket capability scoping registration exists to remove. |
| <a id="engine-version"></a>**Engine version** | The Corvus runtime version a [version](#version)'s [executor](#executor) IL was compiled against, recorded in its [executor manifest](#executor-manifest) (manifest format 2 and later). The [AOT builder](#aot-builder) references a matching runtime and refuses a mismatch, so a deployment's package feed must retain every engine version any live version still pins. |
| <a id="execution-backend"></a>**Execution backend** | The pluggable isolation model a [runner](#runner) dispatches a [run](#run) to: in-process collectible load context, per-run micro-guest, serverless function, or container — an isolation ↔ latency ↔ cost choice. |
| <a id="executor"></a>**Executor** | The compiled assembly generated from a [package](#package) that runs the [workflow](#workflow); loaded per [version](#version) with digest verification against its [executor manifest](#executor-manifest). |
| <a id="fault"></a>**Fault** | A [run](#run) is *faulted* when a [step](#step) errors and `failureActions` do not resolve it: terminal-but-recoverable. The fault record captures step id, attempt, error, time, and retriability. |
| <a id="isolation-model"></a>**Isolation model** | The execution isolation a party names (ADR 0058): `InProcess` (a collectible load context inside the [runner](#runner)) or `Isolated` (an out-of-process [execution backend](#execution-backend), e.g. a serverless function). An [environment](#environment) declares the isolation its [runs](#run) *require* (`requiredIsolation`, defaulting `InProcess`); a runner *advertises* the isolation it provides (`isolationModel`); the start gate and the control plane's admission checks match the two. |
| <a id="isolation-posture"></a>**Isolation posture** | The operator view of the [isolation-model](#isolation-model) match: per environment requiring `Isolated`, whether a live, authorized [runner](#runner) advertising `Isolated` serves it — *covered* (isolated-required runs can dispatch) or *uncovered* (they cannot, until one does). |
| <a id="lease"></a>**Lease** | The advisory single-owner, TTL-bounded claim that stops a horizontally-scaled [runner](#runner) fleet double-advancing one [run](#run). |
| <a id="lease-epoch"></a>**Lease epoch** *(proposed)* | The monotonic counter the control plane stamps on each [lease](#lease) grant, ordering claims over one [run](#run) (ADR 0065). Paired with the [store incarnation](#store-incarnation) it forms the anchor ordering key, so a restore that resets the counter cannot make an old grant outrank a new one. |
| <a id="machine-principal"></a>**Machine principal** | The identity a [runner](#runner) (or any non-human caller) authenticates as, and the single subject the whole [runner ↔ environment binding](#runner-environment-binding) hangs off: a runner registers under it, an [environment administrator](#environment-administrator) authorizes it, and the [runner API](#runner-api) resolves both binding reach and [lease](#lease) ownership from it. Because it is a client rather than a person, it is the client id the token names (`azp`, else `client_id`), falling back to the subject for a deployment identifying its runners by certificate. Registration and the runner API must resolve it identically, since the two disagreeing produces no error anywhere: the runner resolves to no bindings and is offered nothing, exactly as an unauthorized one is. |
| <a id="micro-guest-backend"></a>**Micro-guest backend** | The third [execution backend](#execution-backend) (ADR 0063): `Isolated` execution in a Hyperlight micro-VM on the [runner's](#runner) own machine, with the version's [native binary](#native-binary) (the `linux-musl-x64` target) running under a Unikraft guest kernel. A warm sidecar holds a booted, snapshotted micro-VM per (environment, version) and restores it hermetically for each advance, so every [run](#run) executes in a pristine VM state at local latency; egress is allowlisted to the checkpoint surface and the environment's sources. |
| <a id="native-artifact-attestation"></a>**Native artifact attestation** | The manifest the control plane signs to vouch for a [native binary](#native-binary) (ADR 0055): it binds the binary to its [version](#version) (the [content hash](#content-hash)), its runtime target, its engine version, and its own digest, with a detached signature. Carried under `metadata/native-attestation/<rid>`; a deploy verifies it against a trusted key before deploying the binary, so a binary swapped in storage or transit, or replayed from another version, is caught. The output-side counterpart of the [executor manifest](#executor-manifest) signature. |
| <a id="native-binary"></a>**Native binary** (native artifact) | The per-runtime-target native executable the [AOT builder](#aot-builder) produces from a [version](#version)'s signed [executor](#executor), stored in the [package](#package) as `metadata/native/<rid>`, one per .NET runtime identifier (the **runtime target**). Metadata, so it is excluded from the [content hash](#content-hash): adding or rebuilding a target never changes the version's identity. Native AOT does not cross-compile across operating systems, so each target builds on its own build host. |
| <a id="native-build"></a>**Native build** (build job) | The asynchronous build that produces a [native binary](#native-binary) for one (environment, runtime target): enqueued idempotently per target (re-enqueuing resets it to `Queued` — a rebuild), driven `Queued → Building → Ready \| Failed` by a build worker on the control plane. Producing it is the prerequisite to a [workflow deployment](#workflow-deployment). |
| <a id="nested-trace-record"></a>**Nested trace record** (`subTrace`) | The complete [trace](#trace) of one [sub-workflow](#sub-workflow-step) execution, attached to its parent [step](#step)'s record: `{workflowId, outcome, steps, stepsExecuted, …}` — the same trace shape, recursively. The root trace carries no `workflowId`; sub-traces always do. |
| <a id="re-anchor"></a>**Re-anchor** *(proposed)* | The single operator-signed recovery path for a [tenant anchor](#tenant-anchor) that is lost or legitimately behind the store after a restore (ADR 0065). An operation, not a permission: the operator is shown and signs the exact observed tuple, carrying a strictly monotonic per-run counter so an older signed record cannot be replayed. A rollback or substitution *within* one [store incarnation](#store-incarnation) is deliberately not re-anchorable, because signing it away would bless the attack. |
| <a id="resume"></a>**Resume** | Continuing a [suspended](#wait)/[faulted](#fault) [run](#run) by mode: retry faulted [step](#step), rewind, skip, or **state patch** (an RFC 6902 patch to the run context, then retry). |
| <a id="run"></a>**Run** | One execution of a [workflow](#workflow) [version](#version) (`Pending` → `Running` → `Suspended`/`Completed`/`Cancelled`/`Faulted`), durable and [resumable](#resume). |
| <a id="runner"></a>**Runner** | An execution host that claims and executes [runs](#run); self-registers and heartbeats to the [runner registry](#runner-registry). |
| <a id="runner-api"></a>**Runner API** | The control-plane surface every [runner](#runner) store interaction goes through (ADR 0065): claim, [lease](#lease), [checkpoint](#checkpoint) save/load, timer and message queries, catalog artifact pulls. Deployed as a separately scalable component sharing the store with the governance API, so execution load never rides the governance request path. Runners hold NO store credentials, and **no platform credential is minted for them either**: a runner authenticates with the machine principal it already has (client credentials, private-key JWT, or mTLS through the deployment's IdP), so a decommissioned host leaves no long-lived platform-issued secret to steal. Environment bindings are resolved per request from a bounded cache, which is what gives the [revocation fence](#runner-revocation-fence) its effect, and [lease](#lease) ownership derives from the authenticated principal rather than from a client-supplied owner string. Tenant separation is enforced at the API, not in runner-resident code. |
| <a id="runner-environment-binding"></a>**Runner ↔ environment binding** | One [environment](#environment) per [runner](#runner) (many runners per environment): a runner is provisioned for exactly one environment's [credentials](#credential)/network and must be authorized by that environment's [administrators](#environment-administrator) before it is dispatchable. The lifecycle is `Pending → Authorized`, `Authorized ⇄ Quarantined` ([quarantine](#runner-quarantine)/reinstate), and `Revoked → Authorized` ([revoke](#runner-revocation-fence)/re-authorize); only `Authorized` is dispatchable. The [runner API](#runner-api) resolves a binding by the record's bound machine principal rather than by a runner id, and **no principal may hold a platform binding and a tenant one at once** — that pair is a laundering route out of a sealed environment into the never-sealed platform one, so a principal holding both is bound to nothing at all (ADR 0065 decision 2). |
| <a id="runner-pre-authorization"></a>**Runner pre-authorization** | An administrator authorizing a [runner](#runner) id for an [environment](#environment) *before* any runner has registered under it. It names the machine principal that will register (`expectedPrincipal`) rather than the id alone, so the id cannot be squatted in the meantime (ADR 0065 decision 2); an unnamed pre-authorization is refused. Contrast **register-then-approve**, where the runner registers first and the administrator decides on the row it created. |
| <a id="runner-pre-authorization-withdrawal"></a>**Runner pre-authorization withdrawal** | Removing an authorization record no [runner](#runner) has registered against, freeing the runner id. It exists for one situation: a [pre-authorization](#runner-pre-authorization) that named the wrong principal, which no later decision can correct because the principal never moves once bound. It is **not** how a serving runner is stopped — that is the [revocation fence](#runner-revocation-fence), which keeps the record auditable and expires the runner's [leases](#lease). Withdrawal is refused once a runner has registered under the id (ADR 0027). |
| <a id="runner-quarantine"></a>**Runner quarantine** | Temporarily excluding a faulted [runner](#runner) from new dispatch while its in-flight [runs](#run) drain; the status becomes `Quarantined` (not dispatchable). Reinstated to `Authorized` by authorizing it again, with no re-registration. The temporary counterpart of the permanent [runner revocation fence](#runner-revocation-fence). |
| <a id="runner-registry"></a>**Runner registry** | The store-backed table of [runners](#runner) and the [versions](#version) they host; a runner missing heartbeats goes **Stale**, past TTL it is pruned and its [runs](#run) become claimable. |
| <a id="runner-revocation-fence"></a>**Runner revocation fence** | Permanently removing a compromised [runner](#runner) (status `Revoked`) and stopping its in-flight work at once: revoke expires every [lease](#lease) the runner holds at the store, so an authorized peer reclaims its [runs](#run) immediately and the revoked runner's next checkpoint write conflicts. Enforced in the store, not on the runner (a cooperative self-check is worthless against a compromised host). Returning needs a deliberate re-authorization. |
| <a id="schedule"></a>**Schedule** | A durable [run](#run) of the built-in scheduler workflow (reserved [workflow](#workflow) id `$schedule`, #896) that fires a target [version](#version) on a cron cadence. On each due occurrence it starts the target through the governed [trigger](#trigger) idempotently, advances a watermark, then suspends on a [timer](#wait) until the next; it rides the same wait index, [lease](#lease), and [environment](#environment) pinning as any run, and is excluded from operator run listings. Only a [runner](#runner) advertising `servesSchedules` claims schedule runs for its environment, so the control plane can refuse a schedule in an environment nothing serves. Between fires the scheduler run sits `Suspended` on its timer [wait](#wait); the schedules surface labels this state **Waiting** (rather than `Suspended`, which reads as broken for a cron cadence). |
| <a id="scoped-step-path"></a>**Scoped step path** | The address of a [step](#step) inside nested [sub-workflows](#sub-workflow-step): `parentStepId/childStepId[/...]` (slash-delimited; safe because Arazzo stepIds match `^[A-Za-z0-9_\-]+$`). A bare stepId addresses a root step only. Used by breakpoints (`pause.beforeSteps`), run-to-here (`until.beforeStepId`), and the [trace](#trace)'s `pausedBefore`. |
| <a id="sealed-checkpoint"></a>**Sealed checkpoint** | A [checkpoint](#checkpoint) whose [payload](#checkpoint-payload) is tenant-encrypted under its [environment checkpoint key](#environment-checkpoint-key) while its [envelope](#checkpoint-envelope) stays control-plane-readable (ADR 0065): governance keeps every verb over the run; the platform, its backups, and every other tenant see only ciphertext for the data. |
| <a id="step-into-step-over"></a>**Step-into / step-over** | The debugger verbs over a [sub-workflow step](#sub-workflow-step): step-over treats it as one unit (the parent record's status/outputs); step-into descends into its [nested trace record](#nested-trace-record), the canvas following, breadcrumb back. Descent over a recorded prefix is client-side [trace](#trace) navigation; acquiring a deeper stop is a stateless replay with a scoped `until`. [Resume](#resume) verbs and the durable [cursor](#cursor) stay parent-scoped. |
| <a id="store-incarnation"></a>**Store incarnation** *(proposed)* | The tenant-attested generation of the control plane's durable store (ADR 0065). It increments when the tenant attests a restore, which is what distinguishes "the platform rolled my [run](#run) back" from "I restored a backup and know it". The same observation, opposite responses. |
| <a id="sub-workflow-step"></a>**Sub-workflow step** | A [step](#step) bound to another [workflow](#workflow) (`workflowId` binding). Executes inline within the parent's [run](#run): no child run entity, no separate [cursor](#cursor), its result materialized on the parent step's record. |
| <a id="tenancy-ledger"></a>**Tenancy ledger** *(proposed)* | The deployment's single row recording every [owner group](#owner-group) admitted to hold an [environment](#environment) here (ADR 0065). It is both the census and the interlock. As a census it answers "how many distinct owner groups are there" from one row rather than a scan of every environment. As an interlock it carries an etag that a create introducing a group must compare-and-swap, so two simultaneous introductions cannot both observe a single-group deployment and both commit. Append-only: deleting the last environment of an owner group does not remove it, because a removal cannot prove absence and commit in one operation. It over-refuses rather than under-refuses, and being recorded in it is never an exemption from the rule. Held by `IEnvironmentStore` rather than a store of its own, so a durable deployment cannot be wired with a ledger that is not durable. |
| <a id="tenant-anchor"></a>**Tenant anchor** *(proposed)* | The small write-ahead record, in a store only the tenant can write, holding what the tenant last committed for a [run](#run): the epoch high-water mark, the committed and pending marks (each a [checkpoint digest](#checkpoint-digest) at an ordering key), the [re-anchor](#re-anchor) counter, and the disposition (ADR 0065). It is what makes a control-plane rollback or substitution *detectable* rather than merely undesirable. The control plane holds every [checkpoint](#checkpoint) but cannot rewrite the tenant's record of which one is current. |
| <a id="trigger"></a>**Trigger** | How a fresh [run](#run) is started (as opposed to [resuming](#resume) a suspended one): the HTTP, message, or [schedule](#schedule) trigger surface. All three converge on the governed control-plane start endpoint. |
| <a id="wait"></a>**Wait** | Why a [run](#run) is `Suspended`: a timer (`dueAt`) or a correlated message (`channel` + [`correlationId`](#correlation-id)). |
| <a id="workflow-deployment"></a>**Workflow deployment** | The deployment of a [version](#version)'s verified [native binary](#native-binary) to a function platform for one (environment, runtime target): driven `Queued → Deploying → Deployed \| Failed` by a deploy worker *on the runner* (the runner holds the environment's cloud credentials, ADR 0059), carrying the function invoke URL once `Deployed`. Read-only on the control plane, which records and reports the state the runner drives. |

## Security and governance

Every access decision has **two planes**: WHO can do WHAT (capability scopes) and WHERE (reach).
Both must pass.

| Term | Definition |
|------|------------|
| <a id="access-request"></a>**Access request** | A control-plane resource any principal submits to ask for elevated access to a specific [workflow](#workflow); routed to that workflow's [administrators](#administrator); approval writes an [entitlement](#entitlement). A request can never target a third party, and is decided under the [independent-decision](#independent-decision) rule. |
| <a id="administrator"></a>**Administrator** | A member of a [workflow](#workflow)'s or [environment](#environment)'s governing set (see [environment administrator](#environment-administrator)); the only third-party grant in the access model. |
| <a id="approver-inbox"></a>**Approver inbox** | The queue showing an approver every pending [access](#access-request)/[availability](#availability-request)/[runner](#runner-environment-binding) request across everything they administer, without naming a subject first. |
| <a id="browser-mediated-acquisition"></a>**Browser-mediated acquisition** | Bringing a [source document](#source-document) in through the author's own browser (**paste** the document text, or **upload** the saved file) when it sits behind a browser login/session the control-plane server cannot replay (ADR 0052). The answer for "a document I can open in my browser once I have logged in": the browser is the authenticated agent, and no server-side credential custody is involved. The first-class alternative to a [source fetch](#source-fetch) for session-protected documents. |
| <a id="capability-scope"></a>**Capability scope** | A token capability tier (`catalog:read`, `runs:write`, `credentials:write`, …) gating API operations. Say "capability scope", not bare "scope", where ambiguity is possible. |
| <a id="channel-credential"></a>**Channel credential** | The [credential](#credential) of an AsyncAPI (channel) [registered source](#registered-source) (ADR 0051): the same auth kinds as HTTP, read as credential *shapes* (`bearer` = a token/SAS presented at connect, `basic` = SASL user/password, `oauth2ClientCredentials`, `mtls`), plus the environment's broker **server URL** as non-secret `serverUrl` config (the channel analogue of the HTTP `baseUrl` override). The transport protocol comes from the source document's `servers[].protocol`, never the binding; the [runner](#runner) builds the source's message transport from the binding at bind time via a protocol-dispatched factory. Broker auth is connection-time, so a channel credential — like `mtls` — is connection-scoped and never usage-scoped to an individual run. |
| <a id="connected-provider"></a>**Connected provider** | An OAuth/OIDC provider whose **content API accepts a brokered user token**, registered by a deployment so a [source fetch](#source-fetch) can retrieve a document *as the user* (ADR 0052). This is the git-host and API-platform class (GitHub, GitLab, Azure DevOps, bearer-fronted API catalogs), the **specialized** fetch tier — not a way to reach a portal whose document endpoint is guarded by a browser session (that is [browser-mediated acquisition](#browser-mediated-acquisition)). Configuration: an OIDC issuer (endpoints via discovery) or explicit authorize/token endpoints, a client id + secret reference, scopes, and the host patterns it covers. GitHub is a connected provider whose extra repos/browse surface sits on top of the shared machinery. |
| <a id="credential"></a>**Credential** | A per-[registered-source](#registered-source), per-[environment](#environment) binding of a **[secretRef](#secretref)** plus non-secret configuration. For an OpenAPI source the kinds attach per request (except connection-scoped `mtls`); for an AsyncAPI source the same kinds describe the broker credential — see [channel credential](#channel-credential). Its **status** (`Valid`/`ExpiringSoon`/`Expired`) is derived on read; rotation is re-pointing the reference. |
| <a id="data-key"></a>**Data key** *(proposed)* | The per-encryption AES-GCM key for one [checkpoint payload](#checkpoint-payload), derived from the [payload key](#payload-key) over `(environmentId, keyId, runId, sequence, salt)` with every field length-framed (ADR 0065). Derived, never wrapped and stored, so there is no key blob in the row and no KMS call on the save path. A fresh salt is required per encryption *operation*, never per logical checkpoint, because re-encrypting after a `409` with a cached salt would repeat a `(key, nonce)` pair. |
| <a id="digest"></a>**Digest** (identity digest) | The canonical digest over a stamped identity set — equal iff set-equal. The stable key [administrators](#administrator) are indexed by and removed by; [membership](#membership) lookups enumerate a caller's subset digests against it. |
| <a id="eligibility"></a>**Eligibility** | The PIM-style "you may self-elevate this" grant (*approve-as-eligible* on an [access request](#access-request)): durable permission to activate access JIT without re-approval. Eligible is not active — wielding requires an explicit, audited, time-boxed activation. |
| <a id="entitlement"></a>**Entitlement** | A per-principal stored grant (never in the IdP) binding a subject claim to a [capability scope](#capability-scope) and a [reach](#reach), optionally time-boxed. Capability = token claims ∪ stored entitlements. |
| <a id="external-schema-reference"></a>**External schema reference** | An inputs-schema `$ref` to an attached `jsonschema` document (never a `sourceDescription` — the Arazzo spec pins that enum). The PREFERRED base is the document's absolute root `$id` (its canonical identity); the virtual relative path `schemas/<name>#<pointer>` is the fallback for an `$id`-less document. Packaged alongside the [source documents](#source-document) at [publish](#publish) and registered with the generation resolver under both identities. A reference matching no attached document is a validation error. |
| <a id="governance-audit"></a>**Governance audit** | The retained trace a governance action leaves (design §850): a span on the `Corvus.Arazzo` activity source naming the actor, the target resource, and the outcome, plus an audit-grade log record. Emitted for security-posture changes — [access-request](#access-request) decisions including the [independent-decision](#independent-decision) refusal, and, as the surface is completed, [credential](#credential) custody, [grant binding](#grant-binding) and [rule](#security-rule) authoring, [runner authorization](#runner-environment-binding), [promotion](#promotion), and administrator transfers. Payload-safe by construction: it carries only identifiers and a controlled outcome label, never a step output or secret. The mutation counterpart of the read-access audit that the sensitive [step-output disclosure tier](#step-output-disclosure-tier) applies to a journal read. |
| <a id="grant-binding"></a>**Grant binding** | A `{claimType, claimValue}` → per-verb [reach](#reach) mapping (each verb `Denied`, `Unrestricted`, or a set of [rule](#security-rule) names), optionally pinning further [identity dimensions](#identity-dimension) (`additionalClauses`, matched as a conjunction by [membership](#membership)). A verb's rule set is a **conjunction**: every named rule must admit the row, so adding a rule only ever narrows the grant. Either/or reach is a **union of bindings** (one binding per route) — grants compose as OR across a caller's matched bindings, never within one rule list. The API/wire name is *security binding*; docs and UI say **grant binding**. |
| <a id="grantee"></a>**Grantee** | A real person/team/role/workflow named by governance surfaces, resolved (via the [merged grantee search](#merged-grantee-search), [principal-directory](#principal-directory) search, observed-identity typeahead, or a validated well-known subject id) to the exact **[resolved identity](#resolved-identity)** the deployment stamps. |
| <a id="identity-dimension"></a>**Identity dimension** | One `{dimension, value}` key of a stamped [`sys:`](#internal-sys-tag) identity (e.g. `sys:tenant`, `sys:sub`, `sys:iss`). An **ambient identity dimension** is derived from request context (host, route, gateway header) rather than the token, stamped identically at runtime and grant-authoring moments. |
| <a id="independent-decision"></a>**Independent decision** | The rule that no request is ever decided by its own requester: approve and deny on [access](#access-request) and [availability](#availability-request) requests refuse the requester (403 `own-request`) even when they administer the target, so `decidedBy` always names a second pair of hands; the requester's own exit is *withdraw*. For access requests the bar keys on the request's *subject* (who the decision would empower), not the audit actor. The designed exception is self-elevation of an [eligibility](#eligibility): the eligibility itself was independently decided. |
| <a id="internal-sys-tag"></a>**Internal (`sys:`) tag** | A reserved-prefix [reach label](#reach-label) stamped by the deployment shell: immutable, client-invisible, rejected on user input; the unforgeable key administration and [grants](#grant-binding) rely on. |
| <a id="membership"></a>**Membership** (identity matching) | The governing match rule for administration, [grant-binding](#grant-binding) applicability, and credential [usability](#usability): a principal matches a named identity iff the principal's whole stamped [`sys:`](#internal-sys-tag) identity **contains** it (subset test) — never by exact set-equality, and never against raw token claims. |
| <a id="merged-grantee-search"></a>**Merged grantee search** | The [grantee](#grantee)-search default when a [principal directory](#principal-directory) is configured: the directory (every searchable kind) unioned with the observed-identity typeahead, directory-preferred on a `(kind, value)` collision, as one bounded unpaged result set. A directory failure degrades a merged search to observed results; only an explicit `source=directory` search surfaces it (502). |
| <a id="one-shot-fetch-secret"></a>**One-shot fetch secret** | A header credential the author pastes to authenticate a single server-side [source fetch](#source-fetch) against an endpoint that accepts one in a request header (ADR 0052): a bearer/PAT, an API key (a named header), or Basic — the same schemes the §13 [credential](#credential) machinery models. Used once, never stored, never logged. |
| <a id="owner-group"></a>**Owner group** *(proposed)* | The tenancy an [environment](#environment) belongs to (ADR 0065), stamped at create from the authenticated principal under the deployment's unforgeable internal prefix, and immutable thereafter. Stamped whether or not a row-security policy is configured, because ownership and [reach](#reach) are different questions: an earlier form of the multi-tenancy gate read ownership from the reach policy and was therefore unevaluable in the modes that forbid one. In a mode that does not enforce reach it is provenance only and is never presented as an isolation boundary. Where no reach policy is configured it is read from the deployment's declared owner-group claim; a principal carrying no such claim stamps none, so a deployment that publishes nothing to tell owner groups apart has exactly one. The prefixed key is refused in operator-supplied tags in every mode, so a client cannot name itself into another group through a create body. |
| <a id="partial-identity"></a>**Partial identity** | A [grantee](#grantee) resolution that yields only some of the [identity dimensions](#identity-dimension) the deployment stamps. Flagged because under [membership](#membership) matching a partial identity is *broader* than intended — every principal whose stamped identity contains those dimensions matches it — and authoring a grant on one raises the broadening-overlap advisory naming any subsumed [grantees](#grantee). |
| <a id="payload-key"></a>**Payload key** *(proposed)* | The symmetric key, held only in the tenant's custody and never by the control plane, that every [checkpoint payload](#checkpoint-payload) secret derives from (ADR 0065): the per-encryption [data key](#data-key) plus the per-generation `envelope-mac`, `wait-index`, and `checkpoint-token` subkeys. Its id and rotation are recorded by the [environment checkpoint key](#environment-checkpoint-key) registration. |
| <a id="persona"></a>**Persona** | A named operator archetype the UX targets (operator/SRE, publisher/owner, connections admin, security admin, approver, requester); the demo's persona selector drives [capability-scope](#capability-scope) gating from one source of truth. |
| <a id="principal-directory"></a>**Principal directory** | The pluggable directory seam (LDAP/AD, Keycloak, SCIM, Entra ID, Okta, Google) that searches people/teams/roles and returns [resolved identities](#resolved-identity), each expanded to full [membership](#membership) (a `sys:group`/`sys:role` per membership). It resolves *who*, never *what they may do*. |
| <a id="provider-connection"></a>**Provider connection** | The per-`(principal, provider)` authenticated link to a [connected provider](#connected-provider): minted by the brokered popup flow, the user token held server-side (in-process custody), never handed to the browser. Reach is whatever the user's own identity can see. |
| <a id="reach"></a>**Reach** | Row-level visibility: which records a caller can see/affect per verb (read/write/purge), defined by [security rules](#security-rule) and [grant bindings](#grant-binding). |
| <a id="reach-label"></a>**Reach label** | The umbrella term for the `{key, value}` labels [reach rules](#security-rule) match against: **security tags** on catalog [versions](#version) and [runs](#run) (inherited by runs from their version), **management tags** on [environments](#environment), [registered sources](#registered-source), and [credentials](#credential). Never say bare "tags" — *user tags* are the separate free-form display/filter metadata. |
| <a id="registered-source"></a>**Registered source** | An entry in the control plane's `/sources` registry: a named [source document](#source-document) registered once and referenced by [workflows](#workflow), with per-[environment](#environment) [credentials](#credential). A `jsonschema` source registers a JSON Schema document for **[external schema references](#external-schema-reference)**. |
| <a id="resolved-capability-view"></a>**Resolved capability view** | The Access Overview's `capabilities` section: the [capability scopes](#capability-scope) a [grantee](#grantee)'s matched [bindings](#grant-binding) confer, resolved exactly as the runtime resolver does — expired bindings confer nothing; an [eligible](#eligibility)-only binding shows as *eligible*, not active. |
| <a id="resolved-identity"></a>**Resolved identity** | The full stamped [`sys:`](#internal-sys-tag) identity a [grantee](#grantee) resolves to: the principal's own [identity dimensions](#identity-dimension) plus a `sys:group`/`sys:role` per membership (full membership expansion), exactly as the deployment's runtime resolver stamps it. Grants are authored against it and [membership](#membership) matching compares against it, so the authoring and runtime moments cannot drift. |
| <a id="secretref"></a>**secretRef** | A scheme'd *reference* to secret material in an external store (`keyvault://`, `vault://`, `env://`, …) — never the material itself. Only [runners](#runner) resolve it, at bind time. |
| <a id="security-rule"></a>**Security rule** | A named, reusable boolean row-filter expression over [reach labels](#reach-label), written in the `simple`-[criterion](#criterion) grammar (e.g. `tenant == $claim.tenant`). The reusable WHERE vocabulary a [grant binding](#grant-binding) points at. |
| <a id="source-fetch"></a>**Source fetch** | The server-side retrieval of a remote [source document](#source-document) (`POST /sources/fetch`): no browser CORS, one fetch implementation. Its authentication is **matched to how the endpoint is protected** (ADR 0052): none for a public URL; a header credential the author holds (a [one-shot fetch secret](#one-shot-fetch-secret) or a saved workload [credential](#credential) binding); or a [connected provider](#connected-provider) token where the endpoint's content API accepts one. A document behind the author's own browser session is *not* fetchable server-side and comes in through [browser-mediated acquisition](#browser-mediated-acquisition) instead. The caller then attaches or registers the result; the fetch itself stores nothing. |
| <a id="step-output-disclosure-tier"></a>**Step-output disclosure tier** | The §14 gate on reading a [run](#run)'s recorded step OUTPUTS (its step journal), above ordinary run-metadata [reach](#reach): step outputs can carry the sensitive data the workflow processed (for a KYC flow, identity data). Reading them needs the `runs:outputs:read` [capability scope](#capability-scope) in addition to `runs:read` (the baseline tier). A [version](#version) an author classifies `outputsSensitivity: sensitive` then has its whole journal REDACTED for callers below the stronger grant — write [reach](#reach) on the run — so a read-only observer sees each step marked redacted with no payload, while an operator reads it in full. Every read of the journal is audited (a `workflow.journal.read` span plus an audit log record) at the disclosure tier it reached: *full*, *redacted*, or *refused* (the run was out of reach or absent) — so a sensitive read, disclosed or not, always leaves a trace. |
| <a id="tenant-shell"></a>**Tenant shell** | A deployment wrapper that ANDs a mandated [rule](#security-rule) (e.g. `sys:tenant == $claim.tenant`) and [internal-tag](#internal-sys-tag) stamping into every decision, so multi-tenant isolation is inescapable and users can only narrow within it. |
| <a id="usability"></a>**Usability** | The label-superset test (`IsUsableBy`) governing which [runs](#run) may use a [credential](#credential): the run must carry all the binding's usage tags. Distinct from [reach](#reach) (superset test, not rule match). |
| <a id="wait-index-blinding"></a>**Wait-index blinding** *(proposed)* | Storing a [wait](#wait) match key and [correlation id](#correlation-id) as a MAC under the `wait-index` subkey of the [payload key](#payload-key), so the control plane can match a delivered message to a parked [run](#run) without learning the business key (ADR 0065). The MAC input is length-framed, and includes `environmentId`, so one tenant's `staging` message cannot wake its `prod` run. |

Conflicts found by the 2026-07 docs sweep, and the canonical resolutions. Renames were marked ⚠

|---|----------|------------|
| A | "Scope" means (1) capability tier, (2) the per-verb grant value `Scoped`, (3) the UI's "Scopes" panel which actually edits security *rules*. | (1) is canonical: **capability scope**.
