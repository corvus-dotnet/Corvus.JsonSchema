Patterns Across The Ports

pattern and patternProperties are ECMA-262 regular expressions, and so is the regex format. Every Corvus evaluator answers them as an ECMAScript engine does. This page says how each port matches a pattern, what each refuses, how each limits a match, and where a port still differs from ECMA-262. Each port's own page has the detail.

What every port does

  • Two grammars. A pattern is read with the grammar of the u flag and matched by code point. A pattern that grammar does not accept is read with the Annex B grammar of a pattern with no flag (which accepts \-, \&, a lone { and other things many schemas hold) and matched by UTF-16 code unit, as ECMA-262 matches such a pattern. A pattern neither grammar accepts is refused when the schema is compiled.
  • One oracle. Every port is tested against the ECMA-262 regular expression test data: V8's answers for 98,839 patterns and 4,322,391 texts. Where V8 departs from ECMA-262 the ports follow ECMA-262. A quantifier whose first count is greater than its second is an error whatever the size of the numbers. A group name used twice is an error unless the two groups are in separate alternatives. \p{WSpace} is not a property name ECMA-262 lists. Katakana_Or_Hiragana is a Script value that no character has. The properties are those of Unicode 17.
  • Limits. A schema and an instance can both come from outside, so a pattern has limits of size, refused as too large when the schema is compiled and never as not valid, and a match has a limit of time, 1 second by default.

Where the ports differ

These are the known differences from ECMA-262, or between the ports, that the dataset does not count as wrong answers. Each is a decision recorded here, with an issue where there is work to follow.

.NET

  • A pattern that backtracks without end is bounded only by the timeout. .NET has no engine of its own for the patterns its matchers do not take, so a pattern such as ^(a|aa)+$ on a long run of a runs until RegexMatchTimeout. The ports with their own engine remember where a way has failed and finish such a match. A C# port of that engine, used where the parse tree shows a pattern that can backtrack without end, is to follow (#1025).
  • A pattern proved linear has no timeout. The timeout makes .NET's engines check the clock as they match, which costs up to half the time of a match in the interpreted engine. A pattern whose match is proved to take time in proportion to the text (no backreference, lookaround or word boundary, each repetition of one character or set, and no repetition that can give characters back to another that can take them) is matched with no timeout. See the timeout.
  • A JSON string with a lone surrogate throws. The parser accepts an instance string that holds the escape of half of a surrogate pair, such as "\ud800", and pattern, minLength and maxLength then throw InvalidOperationException (in V4 generated code too). Every other port refuses such a document when it parses it, or reports it as not valid. The 46,438 texts of the dataset's lone-surrogates.jsonl all throw (#1021).
  • format: regex reads a pattern with .NET's parser, not with the ECMA-262 parser that pattern uses, so it can accept a pattern ECMA-262 refuses and refuse one ECMA-262 accepts (#1027).
  • idn-email has a limit of 320 bytes on the whole address. The Rust crate has no limit on the address as a whole. The host name of the address has the limit of 253 characters as A-labels in both (#1029).
  • .NET Framework and a large count. .NET Framework's Regex makes a string of the count of a repetition of one character when it is constructed, so ^a{100000000}$ costs some 200 MB there, and a count no string can reach is written as a part that never matches. .NET does neither.
  • The V4 generated code has the timeout on every pattern, and the four folders of V4 code generated before the change keep their old translations and have no timeout until they are generated again.

Java and Julia

  • Refused lookbehinds. java.util.regex and PCRE2 match a lookbehind forwards, and ECMA-262 matches it backwards. Where a backreference reads a group whose text depends on that, the pattern is refused when the schema is compiled, with a message that says so. See Java and Julia.
  • Julia 1.10 bundles a PCRE2 whose case folding is that of Unicode 14, so thirty case pairs are not equivalent in a case-insensitive backreference there. Julia 1.13 answers exactly.
  • Julia: nested repetitions are left to PCRE2. A pattern such as ^(?:(?:(?:a*)*)*)*b$ is written as (?:(?:(?:a+)+)+)*, which means the same, and PCRE2 backtracks through every way to divide a run among its levels: such a match on sixteen characters reaches the limit of a match. The ports with their own engine finish it.
  • Julia: a pattern too large to be timed. A pattern that PCRE2 holds only without the code that reads the clock, such as an alternation of 3,000 words, is run without it, and its match ends in its first stage.

Python

  • The limit is of time on the clock. The regex package's timeout counts the time of the process on the processor, so with three or more other threads busy a match can run for longer than the limit before it is stopped.
  • A text of more than 1,048,576 characters is not matched by a pattern that is not proved linear, once the first try at a match has been abandoned.
  • re has no limit on the memory of a match. It runs only patterns proved linear.

TypeScript and JavaScript

  • No limit of a match. A RegExp match cannot be interrupted, so a pattern that backtracks without end, on a text made for it, does not return. The answers are those of the host engine, which are V8's on Node and in Chrome. A port of the ECMA-262 engine, which would give a limit and the same answers on every host, is to follow (#1026).
