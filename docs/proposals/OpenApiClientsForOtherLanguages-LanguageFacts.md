Caveats:
- Versions are read from manifests in the working tree (package.json, Cargo.toml, pom.xml, Project.toml, pyproject.toml, version.go, version.rb, DESCRIPTION, composer/Cargo for PHP), not from the registries. PHP row uses the Cargo.toml version.
- Julia 0.1.0 and Pascal 0.1.0 are VERSIONHISTORY/Project.toml values; the Julia memory notes mention a later registry state not visible in the repo.
- Swift: only `docs/JsonSchemaForSwift.md` was used; the current published version is not stated, `from: "0.1.0"` is the install example.
- Column 8 (HTTP client) is entirely my assumption of the conventional choice; the repo docs say nothing, and the ports take a resolver callback instead of fetching. Go/Julia/Java/Pascal READMEs mention `CompileURI`/`compile_schema_uri`/`compileFromUri`/`CompileJsonSchemaFromUri` fetching "through the document resolver", not through an HTTP client.
- Column 9 (type-system facts) is entirely my general language knowledge, not repo content. Java baseline is 17 (pattern-matching switch needs 21).
- "Separate non-collecting path": the docs state "collecting costs nothing when not used" only for TS and Python. For the others I inferred a separate cheap path from the distinct `isValid`/`IsValid`/`valid?` API vs `evaluate`; the repo docs do not say it is zero-cost for each.
- "Y" in the options column is from each doc's options table; all 7 options are listed for every port including Swift and C.
- Typed models "N": none of the per-language docs, READMEs or directory listings mention a generated typed-model surface; I did not search for it exhaustively. The .NET side is the only generator in the repo docs read.
- Java code generation: README says bytecode via shaded ASM; `CodeGen.java` exists, but I found no public emit-to-file API in `Validator.java` signatures.
- Python Rust-backed `generate_module` equivalent: not stated; `generate_module` is documented only for the pure package. Its HTTP/type-system cells are shared with pure Python by assumption.
- PHP, Ruby and R, and Swift and C, read host values in place only for PHP/Ruby/R (and Python-rs); Swift and C take JSON text/bytes and parsed documents only.
- TS `generateModule` and Python `generate_module` produce a module that still imports the package runtime (`@corvus-dotnet/json-schema/runtime`) per the docs.
- Test directory lists for Go and Pascal are abbreviated (`...`); allocation tests exist in Rust, Go, Java, Julia and Pascal by file name only.
- Bowtie directories exist for TS, Rust, Go, Java and Julia only (by directory name); `src-ts/.../test/bowtie-ihop.mjs` and `src-go/.../ihop_test.go` are additional bowtie-related tests.
