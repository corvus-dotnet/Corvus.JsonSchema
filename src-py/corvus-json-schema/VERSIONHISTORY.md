# Version History

The version history of `corvus-json-schema`, the Python port of the Corvus.Text.Json V5 runtime evaluator. It is versioned independently of the Corvus NuGet packages, whose history is in the repository's [VERSIONHISTORY.md](../../VERSIONHISTORY.md).

## V0.1.1

V0.1.1 makes `pattern`, `patternProperties` and `format: regex` answer as V8 does where version 0.1.0 gave another answer, raised an error or refused the schema. There are no API changes.

### Bug fixes

- **`\B` in an empty string.** In ECMA-262, `\B` holds wherever `\b` does not, so it holds in an empty string, which has no word character and so no word boundary. The standard library's `re` module had `\B` never match in an empty string before CPython 3.14, and the package handed `\B` to it unchanged. `cjs.compile({"pattern": "\\B"})("")` returned `False`, where the instance is valid, and so did any pattern that reaches a `\B` with an empty string, such as `^\B$` or `^(\d|\B){2}`. A pattern used for `patternProperties` or `propertyNames` was affected for the property name `""`. `\B` is now translated as "not at a word boundary", `(?!\b)`, which is right on every version. `\b` was already right, and a string that is not empty was never affected. A test checks both at every position of every string of up to three characters from a small alphabet, through the standard library's engine and through the `regex` package. Version 0.1.0 is affected on CPython 3.10 to 3.13, and is not on CPython 3.14.
- **Backreferences.** In ECMA-262 a backreference to a group that has not matched matches the empty string, and the groups inside a repetition lose their values at the start of each iteration. The two engines the package uses fail such a reference and keep a value from one iteration to the next, and the standard library's refuses a reference that comes before its group or is inside it. So `cjs.compile({"pattern": "^(?:(a)|b)\\1$"})("b")` and `cjs.compile({"pattern": "^(?:(a)|b)*\\1$"})("ab")` returned `False`, where the instances are valid, and `^\1(a)$` and `^(a\1)$` raised `SchemaCompilationError`, where the patterns are valid. Each reference is now written from where its group is in the pattern. One that can never be read after its group has matched (it is inside the group, before it, or in another alternative) is written as nothing. One whose group has always matched when it is read stays a reference. For any other, the pattern is run by the `regex` package, where an empty group of the same name resets the group at the start of the pattern and of each iteration. On CPython 3.10 a pattern with a reference to a group inside a repetition is also run by `regex`, because the standard library's engine did not put back what such a group held when it backtracked: `^([^a]?a+){2,3}?\1a$` did not match `aaaa` there. A pattern with no backreference is translated as before.
- **Modifier groups.** The modifier groups of ECMAScript 2025, `(?i:...)`, `(?m:...)`, `(?s:...)` and `(?-i:...)`, raised `SchemaCompilationError`. They now have ECMA-262's meaning, written out by the package so that it is the same on every version of Python. Inside `s` the dot matches any character. Inside `m`, `^` and `$` hold at each of the four line terminators (line feed, carriage return, U+2028 and U+2029), where Python's own multiline flag knows the line feed only. Inside `i`, characters are compared by simple case folding, or by the uppercase form of a UTF-16 code unit in a pattern that is valid only without the `u` flag. So `(?i:k)` matches the Kelvin sign (U+212A) and `(?i:\w)` matches the long s (U+017F), and in a pattern without the `u` flag neither does. The case tables are those of Unicode 16, which V8 13.6 has, in `_casefold.py`. `scripts/embed_casefold.py` makes that file from the Unicode Character Database, and its 2,595 sets were checked against V8 over every character. A backreference inside `i` has its own entry below.
- **An iteration that matches nothing.** ECMA-262 refuses an iteration that matches nothing once the minimum count is met, so such an iteration leaves no group set. Both engines accept one. `cjs.compile({"pattern": "^(?:(a?))+\\1b$"})("ab")` returned `True`, where V8 says the instance is not valid, and so did `^(?:(?=(a)))?\1b` for `"ab"`. A repetition whose body can only match nothing is now written as its body once, or as nothing for a minimum of 0, which is what ECMA-262 makes of it. A repetition that holds a group which is read without its having matched is written as its minimum count and then a rest in which every iteration has to take a character.
- **Group names.** Two groups may have one name when they are in separate alternatives (`(?:(?<a>x)|(?<a>y))\k<a>`), and a name may be written with `\u` escapes (`(?<\u0061>a)\k<a>`). Both raised `SchemaCompilationError`. A name that is not an identifier, as in `(?<1a>a)` or `(?<a-b>a)`, was accepted and is now refused, as V8 refuses it.
- **Patterns the `regex` package runs.** Two faults showed only in a pattern that goes to that package (one with a lookbehind or a Unicode property, say). An empty class, `[]`, matched any character there, because the package reads `[^\s\S]`, which the class was written as, in that way: `(?<=a)[]` was valid for `"ab"`. A reference inside a repetition with a maximum count is not seen by the package where it decides what it need not try again: `(?<=)^(?:(?:(a|)|){2})?(?:x\1)?$` was not valid for `"axa"`. In a pattern with a reference, a repetition that holds a reference or a group that is reset is now written without a count, as copies and alternatives, and a reference to an empty group follows every repetition. A pattern is refused with `SchemaCompilationError` when that would take its translation past 65,536 characters, as a count inside a count can: `^(?:(?:(a)|b){300}){300}\1$` is. `format: regex` still says such a pattern is valid.
- **Patterns that raised from inside an engine.** `a{99999999999999999999}` raised `OverflowError` out of `cjs.compile`. A count of 2,147,483,647 or more is now what it is in V8: no maximum when it is one, and a minimum that no text reaches. A minimum that large over a body that can match nothing, as in `(?:a|){99999999999999999999}`, is refused with `SchemaCompilationError`. `(?:(?=.(a.|){3}|[^a]x|\1)(?<=a)|[ax][^a])*?x$` raised `MemoryError` for `"aaax"`. The `regex` package runs another iteration of a repetition for as long as each one changes what a group holds, even when none takes a character. In a pattern for that package, a repetition that holds a group some reference reads now has to take a character in every iteration past its minimum.
- **A backreference inside a case-insensitive group.** ECMA-262 compares the text of the group and the text at the backreference character by character, each by its Canonicalize: simple case folding with the `u` flag, and the uppercase form of a UTF-16 code unit without it. The package handed the comparison to the `regex` package, whose own comparison is another one. So `cjs.compile({"pattern": "^(?i:(.)\\1)$"})("i\u0130")` returned `True`, where V8 says the instance is not valid (U+0130 folds to itself), and in a pattern that is valid only without the `u` flag `^(.)(?i:\1)\&?$` was valid for `"s\u017f"`, `"k\u212a"`, `"\u00df\u1e9e"` and `"\u1f80\u1f88"`, none of which V8 accepts. Neither engine's comparison can be used. Measured for every cased character against every character, the `regex` package (2026.9.29, which has Unicode 17) equates 104 ordered pairs that ECMA-262 does not with the `u` flag (`i` with U+0130, `I` with U+0131, and the 100 pairs that Unicode 17 added, which V8 13.6 does not have) and 752 without it. The 2024.11.6 release of the same package equates 4 and 652. The standard library's `re` takes `i` and `I` for U+0130 and misses between 100 and 234 of ECMA-262's 3,034 pairs, by the version of Python. The comparison is now written out in the pattern, with the tables of `_casefold.py` that the rest of a case-insensitive group uses: a loop takes one character of the text for each character of the group and asks that the two are the same or are in one set of the tables. The `regex` package runs it. A group that can hold no character with another case, such as `(\d+)`, keeps a plain backreference, and `(?i:(\d+)-\1)` is now run by the standard library's engine. The comparison costs a few microseconds for each character compared, where a plain backreference costs a fraction of one. A group that can hold any character has a translation of about 54,000 characters, which takes about 0.2 seconds to compile and holds about 3 MB.
- **An iteration that matches nothing, inside a lookaround.** A lookaround is left by the first way through it, and its groups keep what that way gave them. ECMA-262 refuses an iteration that matches nothing once the minimum count is met, and goes on to the next way through the body. Both engines accept the iteration and leave the repetition there, so another way is first. `cjs.compile({"pattern": "^(?=((?:|a)*))\\1$"})("a")` returned `False`, where the instance is valid: in ECMA-262 the group holds `a`, and the engines left it empty. So did `^(?=(()()())((c{0,}?)?))\5$` for `"c"`, and `(?<=((?:|a)*))b\1` differed in the same way. In a lookaround with a group that is read outside it, every repetition whose body can match nothing is now written as the repetitions that hold such a group already were, with a rest in which each iteration has to take a character, and the pattern is run by the `regex` package. A fuzz of 24,000 such patterns against V8 found the fault in 5 of the first 8,000.
- **A pattern that is valid only without the `u` flag, by code unit.** Without the `u` flag ECMA-262 reads a pattern and matches a text by UTF-16 code unit, and the package did both by character. That showed for a character beyond the Basic Multilingual Plane. `cjs.compile({"pattern": "^\\-?.$"})("\U00010400")` returned `True`, where V8 says the instance is not valid (the dot takes one of its two code units), `^\-?[^a]{2}$` was not valid for it, and in `^\-?\U00010400*$` the quantifier repeated the whole character, where V8 repeats its second surrogate. Such a pattern is now translated from its code units, and a text it is given is matched as its code units: each character beyond the Basic Multilingual Plane as its two surrogates. That is done only for a pattern that can tell the difference, which is one that can take a character from U+D800 up or that has a lookaround or a `\B` (`\B\&?` holds between the two surrogates of `"a\U00010400a"` and nowhere else in it). For any other pattern, `^[\w\-\.]+\&?$` say, nothing is added to a match, and for one that can, a text of ASCII characters is passed as it is. A group name of a character beyond the Basic Multilingual Plane is still one name (`(?<\U00010400>.)\k<\U00010400>`).
- **A translation an engine does not compile.** A pattern whose translation the `regex` package did not compile was reported as a pattern that is not valid. That is the right answer for a property the package does not have, as in `\p{Nope}`, and it would have hidden a fault of the translation as a refusal. Each `\p{...}` is now asked about by itself when the pattern is read, and a translation that the engine then does not compile raises `RuntimeError` with a message that says it is a fault of the package and shows the translation. None of the 79,221 patterns of the test data, and none of the fuzz patterns, has such a translation.
- **A negated class with a property both ways.** `cjs.compile({"pattern": "[^\\p{L}\\P{L}]"})("ab")` returned `True`, where the instance is not valid: the class takes no character. The `regex` package (2025.9.1 to 2026.9.29 at least) reads a class that has a property and the same property negated as every character, and then drops the `^` before it, so `[^\p{L}\P{L}a]` and `[^\p{sc=Greek}\P{Script=Greek}]` took any character too. A negated class with a `\p{...}` and a `\P{...}` is now written as a character that the class without the `^` does not take, which that reading does not touch. Any other class is written as before.
- **The oldest release of the `regex` package.** The package asked for `regex` 2024.11.6 or later, and it now asks for 2025.9.1 or later. Two faults of earlier releases show in what the package writes for it. A `\b` or `\B` in a pattern that the `regex` package runs is written `(?a:\b)`, as the pattern is compiled without the ASCII flag there. Releases before 2025.7.34 do not apply that flag inside a group, so with one of them `cjs.compile({"pattern": "(?<=\u00e9)\\b"})("\u00e9")` returned `True`, where the instance is not valid, as `\u00e9` is not a word character in ECMA-262. With 2024.11.6, 18 of 4,000 generated case-insensitive patterns had a wrong answer for this reason. Release 2025.8.29 does not compile a dot that takes every character where it is an alternative, as in `(?<![^]|\r)$`, and raised `AttributeError` out of `cjs.compile` for 55 of 14,000 generated patterns with modifiers. With 2025.9.1 the package gives the answers it gives with the latest release for every pattern of the test data and for every generated pattern.

These came from testing the package against the [ECMA-262 regular expression test data](https://github.com/corvus-dotnet/ecma262-regex-test-data), which has V8's answers for 79,221 patterns and their texts, and against patterns that were generated and given to V8. The package gives V8's answer for every pattern and text of the test data, on CPython 3.10, 3.12 and 3.14, through the standard library's engine and through the `regex` package: no valid pattern is refused, no invalid one is accepted, and every answer it gives for the 2,064,911 texts is V8's. That counts the 9,986 texts with a character beyond the Basic Multilingual Plane for a pattern that is valid only without the `u` flag, which could not be counted before such a pattern was matched by code unit. Eight to ten patterns of its `empty-loops` file, by the run, take the standard library's engine more than five seconds for their fifty texts, and one takes the `regex` package that long, where V8 takes milliseconds: they are repetitions inside repetitions that can match nothing, which V8 cuts short and a backtracking engine without its short cuts works through. Every answer for them that comes within three seconds is V8's. Of 188,803 generated patterns with 44.7 million texts (repetitions inside repetitions, lookaheads and lookbehinds with groups, case-insensitive groups and backreferences), on each of the three versions and with every pattern sent to the `regex` package, none is refused, and 191 have an answer that is not V8's. Each of those is one of the three places where V8 13.6 departs from ECMA-262. `README.md` says what is written out so that it is exact, what the two limits are, and where V8 itself departs from ECMA-262.

## V0.1.0

The first release of the Python port of `Corvus.Text.Json.RuntimeEvaluator`, by way of its TypeScript port.

### New features

- **A JSON Schema evaluator for Python.** It covers draft 4, 6, 7, 2019-09 and 2020-12 and passes all 7,967 tests of the JSON-Schema-Test-Suite, including `draft4/optional/zeroTerminatedFloats.json`, which the C# and TypeScript runners exclude. A schema is compiled once into specialised Python, one function per schema node with leaf schemas tested inline, that validates the values `json.loads` produces. It is pure Python, with the `regex` package for the Unicode properties of ECMA-262 patterns.

- **Results and annotations.** Evaluation with a results collector at the Basic, Detailed or Verbose level gives the same rows as the C# `JsonSchemaResultsCollector`, and annotations as `JsonSchemaAnnotationProducer` extracts them.

- **Standalone modules.** A schema can be emitted as a Python module that depends only on the package's small runtime. The `corvus-json-schema` command line generates modules and validates instances.
